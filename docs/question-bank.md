# 题库：20 道题的账本

每题都写清四件事：**测哪个维度 / 选项投给谁 / 为什么这么问 / 改动时要注意什么**。
改题只改 `index.html` 里 `const Q` 的 `t`（题干）和 `o[].t`（选项文案），**别动 `axis`、`w`、`p`**——那是计分骨架。

## 配比

| 维度 | 题号 | 权重合计 |
|---|---|---|
| 发动机 F/P | 1, 5, 9, 13, 16 + 19（w=2） | 7 |
| 取材 N/R | 2, 6, 10, 14, 17 | 5 |
| 规则 W/B | 3, 7, 11, 15, 18 + 20（w=2） | 7 |
| 场域 I/C | 4, 8, 12 | 3（不参与命名） |

情境题（19、20）权重 2：因为它们是"行为题"而不是"自我描述题"，更能分辨真假。

## 逐题

**1. 一个想法刚冒出来，你更可能** · 发动机 · A→F 喷泉 / B→P 打磨
ⓘ 问"想法的下一步"，测的是"生成后是否立刻收束"。这是发散/收敛最干净的切面，不需要用户懂术语。

**2. 要找新点子，你会先翻** · 取材 · A→N 近邻 / B→R 远跳
ⓘ 直接问"信息源"。取材维度只能从"你从哪儿拿料"测，不能从"你觉得自不自己创新"测。

**3. 给你一个现成的模板，你** · 规则 · A→W 场内 / B→B 破框
ⓘ 模板是规则的最小样本。给模板的反应最能暴露"守规 / 改规"。

**4. 好点子通常在** · 场域 · A→I 独行 / B→C 共振
ⓘ 问发生场景而不是问"你喜不喜欢合作"——后者所有人都会答"看情况"。

**5. 你手机备忘录里更像** · 发动机 · A→F / B→P
ⓘ 用生活痕迹代替自我评价。比"你觉得自己点子多吗"可信得多。

**6. 你做出来的东西，灵感常来自** · 取材 · A→N / B→R
ⓘ 换个角度再测一次取材，和第 2 题互为验证（两题都偏同侧才算稳）。

**7. 看到一条"行规"，你的第一反应** · 规则 · A→W / B→B
ⓘ "行规"没有对错，所以回答不会被社会赞许性污染。

**8. 卡住的时候，你更倾向** · 场域 · A→I / B→C
ⓘ 卡点行为比日常偏好更真实。

**9. 做事时最爽的一刻是** · 发动机 · A→F / B→P / **C→触发彩蛋"另起一行"**
ⓘ 这是全卷唯一的"以上都不对"选项。放这里的原因：它是三选里的第三项，且不在最末，愿意点它的人是主动跳出框架，不是顺手选最后一个。
⚠️ 不要把它挪到最后一题——那样点击成本变低，彩蛋就不稀有了。

**10. 有人说你"想得远"，你心里** · 取材 · A→N / B→R
ⓘ 测"自我认知的落差"：心虚地承认自己只是重组，是 N 极最诚实的表达。

**11. 你的作品被评价"不像这一类"** · 规则 · A→W / B→B
ⓘ 被外部否定时的情绪反应，是 W/B 最锋利的探针。

**12. 你更愿意交付** · 场域 · A→I / B→C
ⓘ 用"署名 vs 可被改"测共创倾向，比问"你社不社交"准。

**13. 别人夸你，你更受用哪句** · 发动机 · A→F / B→P
ⓘ 夸奖偏好会暴露你真正看重哪一端。

**14. 遇到真正的难题，你更可能** · 取材 · A→N / B→R
ⓘ 难题场景下，人不会为了好看而假装远跳。

**15. 在一个团队里，你更像** · 规则 · A→W / B→B
ⓘ 角色题：团队里的默认角色比自我宣称更稳定。

**16. 一个项目做到 70%，你通常** · 发动机 · A→F / B→P
ⓘ 70% 是分水岭：这时"想下一个"和"必须推到 95%"是两种完全不同的机器。

**17. 你收藏夹里最多的是** · 取材 · A→N / B→R
ⓘ 收藏夹是"信息的自画像"，很难作假。

**18. 让你改一个已经很成熟的东西** · 规则 · A→W / B→B
ⓘ "改参数"还是"换目标"，是 Boden 探索式 / 转型式的最短判别句。

**19.【情境】周五下午，老板说"下周一给我点新东西"。你先** · 发动机 w=2 · **A→P 打磨 / B→F 喷泉**
ⓘ 死线是最强的行为约束，能测出"平时说发散、真到点子上却收束"的人。
⚠️ **这题的 A/B 是反的**（A 投右极 P）。这是故意的：如果所有题都"选 A 就偏左"，用户选完前十题就能猜出规律，测试会立刻失去可信度。**改题时别把它顺手改回来。**

**20.【情境】有人给你一道"没有标准答案"的题。你先** · 规则 w=2 · A→W / B→B
ⓘ "没有标准答案"时的第一反应，是破框倾向最直接的证据。

## 计分（`index.html` 里的 `compute()`）

1. 每轴左右分别累加权重。
2. 左极占比 ≥ 50% → 取左极字母；否则右极。
3. 三轴字母拼成类型代号（如 `FRW`）。
4. 雷达半径 = `|左占比 - 0.5| × 2`，0 = 正中，1 = 贴边 → 形状越尖，倾向越极端。
5. 彩蛋先判：`另起一行`（写了自由文本）> `复印机`（≥18 题同侧）。

## 想加题 / 减题

- 每轴至少 3 题，否则一个手滑就翻盘。
- 加题时把 `w` 设 1，别用 2（2 只留给情境题，而且现在已经各用了一个）。
- 加完刷新页面即可，不需要构建。
- 题量上到 24 题以上时，先自己用手机测一遍时长；超过 2 分钟，转发率会掉。
